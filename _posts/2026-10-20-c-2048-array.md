我最近在拿 C 语言写一个 2048。

一开始我以为难的是界面。后来发现控制台里用字符画一个 4×4 的格子就够了，真正麻烦的是格子里的数字怎么动。

## 棋盘就是一个二维数组

用 `int board[4][4]` 存棋盘，0 表示空格。打印的时候两重循环，把数字对齐就行：

```c
int board[4][4] = {0};
board[0][0] = 2;
board[0][1] = 2;
```

调通打印以后，我才算真正“看见”了自己写的数据结构。

## 一次移动，其实是三步

以「向左移动」为例，单独处理每一行：

1. 把这一行的非零数字按顺序挤到左边
2. 从左往右扫，遇到相邻且相同的数字就合并，结果放左边
3. 把合并后的数字再往左挤一次

第 3 步很容易漏。漏了的话，`[2, 2, 4, 0]` 向左动完会变成 `[4, 4, 0, 0]`，看起来没问题；但 `[2, 2, 0, 4]` 就会变成 `[4, 0, 4, 0]`，中间空了一格。

## 合并只能合并一次

`[2, 2, 2, 2]` 向左移动，结果应该是 `[4, 4, 0, 0]`，不是 `[8, 0, 0, 0]`。

所以每格合并完要标记一下，这一轮不能再参与合并。我一开始没管，分数直接翻倍，看起来还挺爽，其实是 bug。

## 拆函数比一次性写完省事

我的文件大概长这样：

```text
main.c
├── init_board()    初始化，随机放两个数字
├── print_board()   打印
├── move_left()     四个方向各一个，先写左
├── merge_line()    一行的挤、合、挤
└── can_move()      还能不能走
```

一个函数只干一件事，出错时打印中间结果，就能看出是哪一步错了。
