我踩过两次坑：一次把调试用的 `printf` 推上去了，一次改错文件，把本来想留着的代码删了。

两次都是同一个原因——add 之前没看 diff。

## 常用的三个命令

```bash
git status          # 现在改了哪些文件
git diff            # 具体改了哪几行（还没 add 的）
git diff --cached   # 已经 add 的，commit 之前再看一眼
```

`git diff` 的输出里，`-` 是删掉的，`+` 是新加的。我的习惯是先扫一眼有没有不该出现的行：调试输出、临时代码、密码。

## commit message 写清楚

以前我写 `update`，过两天自己都看不懂。现在按一句话写清楚做了什么：

```text
修正文章 front matter 的日期
新增 2048 的数组笔记
调整首页项目卡片链接
```

不用很长，但要能让人一眼知道这次提交干了什么。

## 和这个博客的关系

我每次写文章也是同样的流程：

1. 在 `_posts/` 建一个 `YYYY-MM-DD-title.md`
2. 本地检查 front matter：`layout: post`、`title`、`date`、`tags`
3. `git diff` 看一遍
4. `git commit`、`git push`
5. 等 GitHub Actions 跑完，打开网址确认

第 5 步别省。有一次我推完就去干别的，晚上打开站点发现新文章没出来——日期写成了明天，Jekyll 不发布未来的文章。

## 一个小目标

以后每次提交前都跑一遍 `git status` 和 `git diff`，哪怕只改了一行。
